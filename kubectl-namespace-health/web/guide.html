Analysis guide

Analyze a simulated Kubernetes snapshot using the same Python health rules as kubectl ns-health.

Health status and CLI exit codes

StatusExitMeaning
Healthy0All evaluated pods are ready and no health indicators were triggered.
Degraded1An unready pod, a restart threshold breach, or a recent warning.
Critical2A failed pod, a critical waiting reason, or no ready pods among workloads being evaluated.
Unknown3No evaluated workloads, indeterminate warning recency, or invalid input. The workspace displays invalid inputs as errors.

How to read a result

Readiness requires a Running pod, a true Kubernetes Ready condition, and no deletion timestamp. Succeeded pods are counted as completed and excluded from evaluated workloads.

The restart threshold applies to each evaluated pod’s cumulative ordinary and init-container restarts. The warning window counts event records up to the snapshot’s reference time.

Event timestamps are tried in this order: series.lastObservedTime, lastTimestamp, eventTime, metadata.creationTimestamp. The window includes both endpoints and excludes future events.

Analyze a custom snapshot

Choose Custom JSON, select the file, enter a declared namespace, then choose Analyze. The request includes the snapshot JSON and analysis settings. Its size limit is 4 MiB.

Supply metadata.namespaces, a timezone-aware metadata.referenceTime, and core/v1 PodList and EventList objects under pods and events.

kubectl ns-health --fixture ./snapshot.json --namespace demo --json
